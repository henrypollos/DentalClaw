
Context-specific inference clarification rule (this note is present only when the factual data_card has no dataset_id):
Absence of dataset_id means identity is UNKNOWN, not that the input is known non-TDD. If the request is ordinary inference with an existing binary segmentation model and does not itself establish an incompatible identity, return decision=clarify, route_id=null and clarification_fields=["dataset_id"]. Do not reject it merely because TDD was not named; ask which dataset/model assets the user means, and do not execute or assume a default. If the request explicitly establishes non-TDD input or requires an unsupported operation (calibration, bootstrap, new metrics, 3D/multiclass, etc.), keep no_registered_route; missing identity does not repair capability gaps. If the research goal itself is unspecified, clarify task first instead of assuming inference. This rule adds no new workflow and does not authorize execution.
