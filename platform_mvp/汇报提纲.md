# 汇报提纲

## 1. 开场：先承认方向调整

可以这样说：

> 上次会议后，我理解老师的重点不是让我继续做 benchmark，而是先把 DentalClaw 作为工具平台的最小底座搭起来。因此我这次把工作从 30 条 intent 评测转到平台 MVP：一句话输入、离线方法选择、调用既有代码、生成结果证据。

## 2. 当前 MVP 的边界

强调边界，不要显得发散：

- 只做牙科 CV。
- 先只支持推理和私有数据训练。
- 只调用既有框架和已登记方法。
- 不做跨框架自动搜索 baseline。
- 不把 benchmark 作为论文主线。

建议说法：

> 我先把范围收窄到老师说的 CV 工具能力，当前平台不追求开放域自动找所有模型，而是通过离线方法表先保证医生的一句话能落到可控流程上。

## 3. 这次新增了什么

展示 `platform_mvp/`：

```text
platform_mvp/
  method_registry.json
```

说明三件事：

4. `generate_readiness_matrix.py` 是多任务状态矩阵。
5. 已有 `mvp_fullflow/` 是可执行 adapter，负责真实 TDD 2D 分割推理报告。

## 4. 讲平台流程

可以用这段：

```text
用户一句话
  -> 解析 dataset/task/modality/mode
  -> 查离线方法表
  -> 选择可执行路线或 planned adapter
  -> 调用已有 DentalClaw 脚本
  -> 收集 manifest、summary、report、overlay
```

重点强调：这不是只生成计划，已接通路线会真的调用已有代码。

## 5. 现场可以展示的命令

plan-only：

```bash
sh platform_mvp/run_platform_mvp.sh \
  --intent "用 TDD 全景片做牙齿二值分割推理，并生成病例报告"
```

快速执行 demo：

```bash
sh platform_mvp/run_platform_mvp.sh \
  --intent "用 TDD 全景片做牙齿二值分割推理，并生成病例报告" \
  --execute \
  --reuse-inference \
  --reuse-fullflow-run artifacts/mvp_runs/tdd_binary_fullflow_20260709_085641 \
  --run-dir artifacts/platform_mvp_runs/tdd_platform_demo
```

说明：`--reuse-inference` 是为了会议展示更快，不重复跑完整 nnUNet 推理；完整推理之前已经跑通。

超分执行 demo：

```bash
sh platform_mvp/run_platform_mvp.sh \
  --intent "对 TDD 全景片做超分辨率增强并输出质量报告" \
  --execute \
  --case-id 100 \
  --run-dir artifacts/platform_mvp_runs/super_resolution_platform_demo
```

私有数据预检查：

```bash
python platform_mvp/validate_private2d_package.py \
  --data-root data/private01 \
  --mode private_train \
  --out-dir artifacts/platform_mvp_runs/private01_validation
```

生成老师汇报包：

```bash
python platform_mvp/generate_readiness_matrix.py \
  --out-dir artifacts/platform_mvp_runs/readiness_matrix_latest

python platform_mvp/generate_report_pack.py \
  --out-dir artifacts/platform_mvp_runs/advisor_report_pack_latest
```

## 7. 已有结果怎么讲

可以这样说：

> 当前已经跑通 TDD 2D 牙齿二值分割推理报告闭环。测试集 100 个病例，mean Dice 0.9130，mean IoU 0.8549，mean HD95 12.9732。平台层可以从一句话自动选择这条路线，并调用已有 full-flow 生成报告和证据。

## 8. 对 planned adapter 的解释

老师可能会问：私有数据训练、3D、异常检测、超分有没有做？

建议回答：

> 我这次先把它们放进离线方法表，并标注状态。对超分，我已经接了一个可执行的 bicubic MVP baseline，能输出超分图、对比图、PSNR/SSIM 和报告。对私有 2D 训练，我已经补了输入契约和预检查脚本，并用 `data/private01` 做了真实检查：它有 139 个 DICOM 图像，但没有 mask/label，所以平台会停止监督训练。3D 分割已有 ToothFairy3 QC 基础，异常检测还需要绑定 baseline/entrypoint。下一步不是重新设计平台，而是逐个把 adapter 接到现有代码或新 baseline 上。

不要说“都已经完成”。要说“平台机制已准备好，当前 TDD 2D 分割和 2D 超分已经真实接通，其他路线有清晰接入门槛”。
