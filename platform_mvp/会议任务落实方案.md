# 会议任务落实方案

## 1. 老师真正要的东西

根据 `refer/会议总结2`，老师对义瑞这部分的要求已经从“设计 benchmark 和评测方式”收敛为“尽快搭出工具平台底座”。核心不是证明 agent 在 30 条 intent 上路径匹配，而是证明 DentalClaw 可以作为一个医生可用的 CV 工具平台：

```text
医生一句话
  -> 平台理解任务
  -> 平台自动选择已有方法
  -> 平台完成推理或私有数据训练
  -> 平台产出报告和证据
```

当前最重要的变化是：论文定位要从 benchmark 转回工具平台。benchmark 只能作为后续验证手段，不能成为主线。

## 2. 任务边界

老师强调不要发散，因此当前 MVP 边界定为：

| 维度 | 当前边界 |
| --- | --- |
| 领域 | 牙科 CV |
| 任务模式 | 推理、私有数据训练 |
| 方法来源 | 离线预置方法表优先 |
| 框架范围 | 既有 DentalClaw 代码和已接入框架 |
| 不做 | 跨框架自动搜索 baseline、开放域医学问答、临床决策自动生成 |

这个边界的好处是，汇报时可以避免老师继续追问“为什么做这么多但跑不通”。我们主动承认边界，并展示一个真实跑通路线。

## 3. 本次新增实现

本次新增 `platform_mvp/`，它与已有 `mvp_fullflow/` 的关系是：

```text
platform_mvp/     负责平台层：一句话解析、方法选择、workflow 计划、证据收集
mvp_fullflow/     负责任务层：TDD 2D 分割推理、指标评估、病例报告
```

新增文件：

- `method_registry.json`：离线方法表，记录平台支持什么、怎么选、能否执行。
- `private_data_contract.json`：私有 2D 训练输入契约。
- `run_platform_mvp.py`：一句话平台编排器。
- `run_platform_mvp.sh`：shell 运行入口。
- `validate_private2d_package.py`：私有数据训练前置检查脚本。
- `generate_report_pack.py`：老师汇报包生成脚本。
- `README.md`：运行指南。
- `会议任务落实方案.md`：本文件，用于解释老师要求如何落地。
- `汇报提纲.md`：会议汇报稿。
- `Adapter接入规范.md`：planned adapter 接入规范和验收门槛。

## 4. 平台架构

当前架构故意保持最小：

```text
User intent
  |
  v
Intent Parser
  - dataset: TDD / Private2D / ToothFairy3 / unknown
  - task_family: segmentation / anomaly_detection / super_resolution / detection / classification
  - modality: 2d / 3d
  - mode: inference / private_train
  |
  v
Offline Method Registry
  - executable route
  - planned adapter
  - unsupported route
  |
  v
Workflow Plan
  - parse
  - registry lookup
  - data/QC
  - training or inference
  - report
  - evidence collection
  |
  v
Execution Adapter
  - current executable adapter: mvp_fullflow/run_mvp_fullflow.py
  |
  v
Evidence Package
  - platform_plan.json
  - platform_summary.md
  - execution_result.json
  - delegated full-flow manifest/report
```

## 5. 离线方法表如何对应老师的“离线建表”

老师提到“离线建表”和“联网查询”双轨并行。当前先实现离线建表：

| 方法 ID | 状态 | 作用 |
| --- | --- | --- |
| `tdd_2d_segmentation_infer_report` | executable | 已跑通的 TDD 2D 分割推理报告 |
| `private_2d_segmentation_train` | planned_adapter | 私有 2D 牙科影像分割训练 |
| `toothfairy3_3d_segmentation_infer_or_train` | planned_adapter | 3D CBCT 分割 |
| `dental_anomaly_detection` | planned_adapter | 异常检测 |
| `dental_2d_super_resolution` | executable | 2D 超分 MVP baseline |

这样做的意义是：即使后续接入更多模型，平台结构不用变，只需要补 registry 项和 adapter。

其中超分路线已经从 planned adapter 推进为 executable。当前实现是一个轻量 bicubic MVP baseline，用于证明平台可以执行超分任务并收集图像、PSNR/SSIM 和报告。它不是最终论文级超分模型，后续仍应接入学习型 baseline。

## 6. 私有数据训练的当前实证

老师强调系统要支持私有数据训练，因此本次额外补了私有 2D 数据输入契约和预检查脚本：

```text
platform_mvp/private_data_contract.json
platform_mvp/validate_private2d_package.py
```

已对当前仓库中的 `data/private01` 做了真实检查：

```text
image_count = 139
mask_count = 0
paired_case_count = 0
terminal_policy = stop_without_training
```

这说明当前私有数据包可以进入数据登记或 QC，但不能进入监督分割训练。这个结果很适合汇报，因为它体现了平台的安全边界：支持私有训练不等于在缺标签时硬跑训练或伪造指标。

## 7. 已经可以展示的真实闭环

当前真实跑通路线：

```text
用 TDD 全景片做牙齿二值分割推理，并生成病例报告
```

平台处理过程：

1. 解析出 `dataset=TDD`。
2. 解析出 `task_family=segmentation`。
3. 解析出 `modality=2d`。
4. 解析出 `mode=inference`。
5. 选择 `tdd_2d_segmentation_infer_report`。
6. 委托 `mvp_fullflow/run_mvp_fullflow.py`。
7. 复用已有推理结果并重新生成报告和汇总。

已有 full-flow 证据：

```text
artifacts/mvp_runs/tdd_binary_fullflow_20260709_085641
```

关键指标：

| 指标 | 数值 |
| --- | ---: |
| case_count | 100 |
| mean_dice | 0.9130 |
| mean_iou | 0.8549 |
| mean_hd95 | 12.9732 |
| pixel_accuracy | 0.9832 |

这条路线可以作为下次会议的主要 demo。

## 8. 为什么现在不继续扩 benchmark

之前的 benchmark 工作并非废弃，但它的定位要降级：

```text
benchmark = 后续验证平台 routing 是否稳定的工具
platform MVP = 当前论文和汇报的主线
```

老师反对的是把论文主线做成 benchmark，而不是反对测试。后续可以把 30 条 intent 作为自动化回归测试，但这不能替代平台真实执行闭环。

## 9. 下一步工程计划

下一步按老师优先级推进：

1. 把 `private_2d_segmentation_train` 从 `planned_adapter` 接成可执行路线。
2. 为私有数据训练定义最小输入包格式：images、masks、dataset metadata、split policy。
3. 接入数据 QC 和 nnUNet export，复用现有训练入口。
4. 为 ToothFairy3 3D 分割补一个最小 inference 或 QC demo。
5. 将超分任务从 bicubic MVP 升级到学习型 baseline，并明确真实配对/非配对数据下的评价策略。
6. 为异常检测明确标签需求和失败策略：没有标签时只允许推理或拒绝训练，不能伪造指标。

## 10. 汇报结论

本次可以向老师汇报：

> 我已经把方向从 benchmark 调整为平台 MVP。现在平台底座包含离线方法表、一句话解析、workflow 计划和可执行 adapter。TDD 2D 分割推理报告闭环已经跑通，能够产出指标、报告和 overlay；2D 超分也已经接入一个可执行 MVP baseline，能够产出超分图、PSNR/SSIM 和对比报告。后续会按同一 registry-adapter 结构接入私有数据训练、3D 分割和异常检测。
